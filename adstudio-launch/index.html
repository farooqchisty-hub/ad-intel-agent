Blockers

1. Fixed 3 Nov: ads.brevo.com is on the pixel's allow list

The site loads the same pixel MagicFit used (569439912209998, "PushOwl Pixel"), but its traffic permissions left out ads.brevo.com, so Meta dropped every browser event there. With your OK I added ads.brevo.com and subdomains to the allow list (Events Manager, PushOwl Pixel, Settings, Traffic permissions). Meta now serves the domain the full pixel config (446 KB, the same as pushowl.com, instead of the 46 KB blocked one), and a test visit fired MagicfitPageView to Meta. PageViews, the click ID cookie and the retargeting pool now build from today.

CPMA re-checks this before every build and refuses if it ever regresses.

2. Built 3 Nov, all paused: waiting for your Go live

You released the hold and asked for the build at once, so it ran outside the call windows under a one-off, logged exception (47 Meta calls, 30 writes, all succeeded). ads.brevo.com says "3 Free generations, one-time" and, elsewhere on the same page, "You get 2 free generations to try out Ad Studio". Every film and every ad promises 3. Fix the "2" line before traffic arrives.

Owner: Ad Studio web team.

4. Confirm a UGC video counts as one of the 3 free ads

Ad set 3 promises "your first UGC creator free". PostHog shows Free-plan users whose first generation was a VIDEO_AD (65 to 75 credits), which supports it, but the plan's exact rule (3 generations or a credit amount) should be confirmed.

Owner: Ad Studio product.

5. Server-side sign-up event: confirm it carries click IDs

MagicfitSignUp reaches the pixel server-side (1:1 with PostHog SignUp: 15 and 15 since 20 Oct). For Meta to credit the right ad it needs fbc/fbp, hashed email, IP, user agent, event_id and event_source_url. The browser click ID cookie (_fbc) is set on ads.brevo.com since the 3 Nov fix, so the server event can pass it on.

Owner: Ad Studio engineering.

CPMA and the dashboard

  • A third silo: Ad Studio runs as its own CPMA deployment (cpma-adstudio) with its own database, storage and queues, the same way Vital Vogue does. Pick Ad Studio in the brand switcher at cpma-agent.pages.dev.
  • Shared account, split cleanly: the PushOwl silo drops every MagicFit or Ad Studio campaign (by name, or because its ad sets optimise to a Magicfit event); the Ad Studio silo keeps only those. Each silo can write only to objects it tracks, so neither can touch the other's campaigns.
  • Conversions: sign-ups are read from Meta's conversions field (custom events are only named there); headline metric is cost per sign-up (CPS), with a $6.50 target and a $10 ceiling, provisional until two weeks of data.
  • History: MagicFit's campaigns since Jul 2025 load into the Ad Studio dashboard in tomorrow's 09:00 IST window (queued), so the Command Center opens with the baseline above.
  • Launch flow: the plan check at GET /api/adstudio/plan lists what blocks; the build (POST /api/adstudio/build) runs in the next Meta window, uploads the films, creates the exclusion audience, campaign, ad sets, creatives and ads, all paused, and posts a Go live card with thumbnails. Approving that card is the only switch that spends.
  • Its own loop: after each sync window, the Ad Studio program loop judges the launch ads (the evergreen engine skips program campaigns, as it does for BFCM), pauses clear losers and raises cards. See Optimisation.
  • Off in this silo: PushOwl's BFCM jobs and the evergreen weekly test batch (logged as skipped); production is on hold, so the agent renders nothing for Ad Studio unless you ask.
