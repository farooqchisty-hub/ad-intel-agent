5. Owl Portal signups that become installs

A portal signup is only half the job. This is how an install that follows a portal signup gets tracked today. There are two paths, and neither one credits the install to the ad yet.

Why nothing has matched yet

  • Email is the only link. The signup event carries the email but no store. If someone signs up with a different email from the one on their store, the match fails.
  • The store-select event is empty. owl_portal_store_select (13 events) arrives with no email and no store domain, so it can't tie a signup to a store.
  • The install event can't help either. PushOwlAppInstall carries only the store subdomain, with no email or click ID.
  • Some signups may simply not have installed yet. The click ID stays valid for 90 days, so later matches still upload.

The fix (engineering, one field)

  • Send the store domain on owl_portal_store_select (or on owl_portal_connect_shopify) together with the same user's email or user ID. The matcher then joins by store, which is exact, instead of by email. No change is needed on the Google Ads side.

10. Known gaps

  • Unattributed installs: about a third of GA4 installs have no source. Fix: cross-domain linking on the Google tag (needs a tag admin).
  • Portal ignores gbraid/wbraid: iOS clicks without a gclid can't be credited.
  • Matched installs don't steer bidding: Store install (import) is secondary on purpose. Making it primary would change the goal mid-campaign.
  • Search can't point at the App Store by keyword override: keyword links on apps.shopify.com were disapproved (destination mismatch) because the ads display pushowl.com. Sending Search to the App Store needs new ads with an App Store final URL, which needs Google's identity check.
  • PushOwlAppInstall events carry only the store subdomain, so portal installs are matched through Intercom by email or store.
