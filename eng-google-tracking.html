Fix Owl Portal install tracking for Google Ads

Google Ads has recorded 0 conversions from the Owl Portal since the GA4 import was set up in May 2025, so the Owl Portal campaigns bid blind. This doc explains the three breaks, what to change, and how to test it. Most of it is small: a missing event call, a URL parameter list, and two IDs in a backend payload.

Summary

1. The install event isn't sent

owl_portal_connect_shopify hasn't fired since about Aug 2025. The constant still exists in the dashboard code, but nothing calls it. The "Connect with Shopify" button only sends a PostHog event.

2. Events arrive without a session

All owl_portal_* events go browser → PushOwl backend → GA4 (Measurement Protocol) with no client_id, session_id or page. GA4 can't tie them to the ad click, so Google Ads can't either. That's why owl_portal_signup (446 events in 90 days) also imports 0.

3. The click ID is dropped on the way

The landing page CTA copies only the 5 utm tags, so gclid, gbraid, wbraid and _gl are lost. The two sites use different GA4 properties, cross-domain linking doesn't include dashboard.pushowl.io, and the dashboard tag only loads after login.

Cost of the gap

The 4 Owl Portal YouTube campaigns (Demand Gen, Maximize conversions) spent $4,528 in 90 days with 0 conversions. With nothing to learn from, Google can't find installers.

Definition of done: a test click on a Google ad lands on the Owl Portal, connects a Shopify store, and within 48 hours Google Ads shows 1 conversion on the install action, attributed to that campaign.

The fixes In order. E1 to E4 are required; E5 makes it robust.

Dashboard / backend

E1. Send owl_portal_connect_shopify when the store actually connectsP0

Fire it server-side when the Shopify OAuth callback succeeds (the api.pushowl.io/auth/v1/pushowl/shopify flow), not on the button click, so it counts real connections only. Keep the existing PostHog click event as it is.

  • Once per shop: skip if this shop has already sent it (store a portal_connect_sent_at on the merchant).
  • Only for merchants who came through the Owl Portal (the portal sign-up created the account).
  • Send it through the same relay as the other portal events, with the fields in E4.
Done when: connecting a test store shows 1 owl_portal_connect_shopify in GA4 DebugView / Realtime for property 393519649.
Webflow (pushowl.com landing pages)

E2. Keep the click IDs on the landing page CTAP0

On /lp/email-marketing and /lp/email-marketing-strategy (and any page with the same CTA script), copy the click IDs along with the utm tags:

// in the CTA click handler
const KEEP = ["utm_source","utm_medium","utm_campaign","utm_term","utm_content",
              "gclid","gbraid","wbraid","_gl","fbclid"];
const here = new URLSearchParams(location.search);
const out = new URL(btn.dataset.base);
for (const k of KEEP) if (here.get(k)) out.searchParams.set(k, here.get(k));
window.open(out.toString(), "_blank");

Better still, make the CTA a real <a href> and let the Google tag's linker decorate it (this also needs E6).

Done when: opening the LP with ?gclid=TEST123&utm_source=x and clicking the CTA lands on the sign-up page with gclid=TEST123 in the URL.
Dashboard (onboarding portal)

E3. Capture and keep the click ID through sign-up and the magic linkP0

  • On /onboarding-portal/sign-up, read gclid, gbraid, wbraid (and utm tags) from the URL and send them in initiateSignup query_params.
  • Store them on the merchant record with the time of the click (click_ids: {gclid, gbraid, wbraid, captured_at}). Carry them through the magic link the same way utm tags already survive.
  • Load the GA4 tag G-MESRBYCSCD on the pre-login onboarding-portal routes, not only after login, so the ad session starts on the sign-up page. Save the browser's _ga and _ga_MESRBYCSCD cookie values on the merchant at sign-up too (used in E4).
  • Point the existing clickid property builder at the stored value instead of the current URL.
Done when: a merchant created from a URL with ?gclid=TEST123 has click_ids.gclid = TEST123 after the magic link, on a different tab or device.
Backend

E4. Send session fields on every Measurement Protocol eventP0

GA4 only joins a server event to the ad session when it carries the same client_id and session_id the browser tag used. Add them to the relay in /analytics/track/events/:

POST https://www.google-analytics.com/mp/collect?measurement_id=G-MESRBYCSCD&api_secret=<secret>
{
  "client_id": "1234567890.1727300000",      // from the _ga cookie "GA1.1.1234567890.1727300000"
  "user_id": "<merchant id>",
  "timestamp_micros": 1727300000000000,       // when it happened; must be within 72 hours
  "events": [{
    "name": "owl_portal_connect_shopify",
    "params": {
      "session_id": "1727299000",             // from _ga_MESRBYCSCD "GS1.1.1727299000.1..."
      "engagement_time_msec": 100,
      "page_location": "https://dashboard.pushowl.io/connect-store",
      "gclid": "TEST123",                     // from E3, when present
      "shop_domain": "store.myshopify.com"
    }
  }]
}

Use the cookie values saved in E3 when the event is sent from the OAuth callback (no browser in that request). Test with /debug/mp/collect first: it returns validation messages.

Done when: in GA4, the test event shows session source / medium google / cpc and the test campaign name, not "(not set)".
Backend

E5. Upload the conversion to Google Ads directly (recommended)P1

The GA4 import breaks whenever the session join fails (cookies blocked, a different device after the magic link). An offline click upload only needs the stored click ID, so it's the reliable path. Marketing creates the conversion action (see below) and gives you its ID.

POST https://googleads.googleapis.com/v24/customers/8465254800:uploadClickConversions
{
  "conversions": [{
    "gclid": "TEST123",                        // or "gbraid" / "wbraid" when there's no gclid
    "conversionAction": "customers/8465254800/conversionActions/<id from marketing>",
    "conversionDateTime": "2026-09-26 12:00:00+05:30",
    "orderId": "<shop_domain>"             // dedupes repeats
  }],
  "partialFailure": true
}
  • Send it in the same place as E1 (OAuth success), once per shop, only when a click ID was stored within the last 90 days.
  • Optional, for users with no click ID: add enhanced conversions for leads (userIdentifiers: [{hashedEmail: sha256(lowercased trimmed email)}]), since the portal captures email at sign-up.
  • Needs a Google Ads API developer token and OAuth for account 8465254800. If that's a blocker, tell marketing: the agent can do the upload if you post the shop, click IDs and connect time to it.
Done when: Google Ads › Goals › Conversions › Diagnostics shows the upload accepted, and the test conversion appears on the campaign within 24 to 48 hours.
Marketing (GA4 UI)

E6. Add the dashboard to cross-domain measurementP2

In the G-4MLSL4TZ89 tag settings, under Configure your domains, add dashboard.pushowl.io next to pushowl.com. This only helps together with E2 (a real link) and E3 (the tag loading before login). The GA4 Admin API doesn't expose this setting, so it's a UI change.

Test plan

  1. Open https://www.pushowl.com/lp/email-marketing?gclid=TEST-<date>&utm_source=googleads&utm_medium=cpc&utm_campaign=tracking-test in a clean browser profile.
  2. Click the CTA. Check the sign-up URL keeps gclid (E2).
  3. Sign up, open the magic link, connect a development store (E3). Check the merchant record has the click ID and cookie values.
  4. GA4 DebugView (property 393519649): owl_portal_signup and owl_portal_connect_shopify arrive once each, with session source google / cpc (E1, E4).
  5. For a real attribution test, run it from a real ad click on a paused-then-enabled test ad (a fake gclid is rejected by Google Ads). Google Ads shows the conversion within 24 to 48 hours (import) or after the upload (E5).
  6. Connect the same store again: no second event or upload (once per shop).

Security note

The GA4 Admin API returns the Measurement Protocol secret in plain text to anyone with Admin access to the property. Rotate the secret used by the backend relay when you ship E4, and keep the new one in the backend's secret store only.
