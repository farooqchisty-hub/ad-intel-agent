Google Ads tracking: what we need from engineering

Keep your server-side events. Add the visitor's GA IDs to them so Google can match each signup to the ad click. No Tag Manager needed.

Change from the earlier version: this page used to ask you to add Tag Manager (GTM-W9BPQ9) to the portal. Skip that. Your backend stream already does most of the work, so the fix is smaller.

Why

You send the signup and install events server-side to Pushowl Dashboard (Backend) - GA4 (stream G-MESRBYCSCD). That property is already linked to our Google Ads account, and owl_portal_signup is already a key event that Google Ads imports. Good.

The problem: the events arrive without the visitor's GA IDs, so GA4 can't tell which visit (and which ad click) they belong to. In the last 90 days all 446 owl_portal_signup events landed as "Unassigned", so Google Ads gives credit to no ad and records 0 conversions.

The ad click ID (gclid) already reaches the signup page: pushowl.com started forwarding it today, and we tested it. Once the tag is on that page and your events carry the visitor's IDs, GA4 can link it all together.

Engineering

Step 1. Load the dashboard Google tag on the signup page too Required

  • The portal already loads G-MESRBYCSCD, but only after login. It's in the same block in _app as Segment, Intercom and the Meta pixel.
  • Load it on every portal page, including https://dashboard.pushowl.io/onboarding-portal/sign-up. That's where people arrive from the ads, with the gclid in the URL.
Engineering

Step 2. At signup, read the visitor's GA IDs and save them Required

In the browser, before or during the signup request:

gtag('get', 'G-MESRBYCSCD', 'client_id',  (cid) => { /* send as ga_client_id */ });
gtag('get', 'G-MESRBYCSCD', 'session_id', (sid) => { /* send as ga_session_id */ });
  • Send both values to the backend with the signup request and save them on the user or store record.
  • If they're missing (for example, an ad blocker is on), carry on as today.
gtag 'get' reference
Engineering

Step 3. Add them to every server-side event Required

For owl_portal_signup, owl_portal_store_select, owl_portal_connect_shopify and PushOwlAppInstall:

{
  "client_id": "<saved ga_client_id>",
  "events": [{
    "name": "owl_portal_signup",
    "params": {
      "session_id": "<saved ga_session_id>",
      "engagement_time_msec": 1
    }
  }]
}
  • Use the real client_id instead of a generated one. Without it, GA4 can't link the event to the visit.
  • For later events (like the Shopify connect), use the same client_id. If that request comes from the browser, send its current session_id.

Engineering

Step 4. Check owl_portal_connect_shopify Please check

It's set up as a key event, but GA4 received 0 of them in the last 90 days. In the same period it got 446 owl_portal_signup and 79 owl_portal_store_select. Is it still being sent, or did the name change?

How to check it works

  1. Open the landing page with a test click ID, click Get started, and sign up with a test store.
  2. In GA4 (Pushowl Dashboard (Backend) - GA4), check Admin → DebugView or Reports → Realtime. owl_portal_signup should show up linked to that visitor.
  3. A day later, owl_portal_signup in Reports should start showing channels other than "Unassigned".

What marketing does after that No engineering work needed

  1. Point the 4 YouTube campaigns back at the "OwlPortal SignUp" goal, and add the Shopify connect once it's firing.
  2. Watch Google Ads for the first conversions linked to an ad, then let bidding optimise for them.

FYI: Tag Manager Nothing to do

  • GTM-W9BPQ9 (on pushowl.com) is an old container that only has Universal Analytics tags, which Google switched off in 2024. It does nothing useful today.
  • GTM-NNBGKXMQ (in your PushOwl Tag Manager account) is empty and isn't installed anywhere.
  • This fix doesn't need either one.
