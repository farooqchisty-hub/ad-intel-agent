What I found Read directly from the PushOwl ad account and pixels on 25 Sep 2026. Nothing was changed.

Install tracking already works

The Shopify App Store listing sends server-side events to PushOwl New Pixel. In the last 30 days: 5,549 listing views, 2,629 install clicks and 2,224 installs, sent as Purchase. The old PushOwl Pixel also gets a custom PushOwlAppInstall event (2,212), almost certainly from PushOwl's own backend.

Ads barely drive installs today

Of those installs, Meta attributed only 55 in 90 days to ads, against $16,277 of spend. The spend went to a managed-service (CaaS) lead campaign. There's no install CPI baseline yet: the first two weeks will set it.

The only live campaign is off-goal and blocked

"pushowl caas july" optimises to Lead on the old pixel, not installs. All 15 of its ads are disapproved, which is why it stopped spending on 7 Sep. Disapprovals count against account standing, so fixing them comes first.

The agent measures the wrong thing

Its CPA counts leads and registrations. The drafts it builds are OUTCOME_TRAFFIC campaigns. Both have to move to each campaign's goal event: Purchase (install) on PushOwl New Pixel.

200+ audiences, mostly not PushOwl

70 custom, 96 lookalike, 31 website and 3 engagement audiences, in a single page with more beyond it. Most are named for Sendinblue, Mailchimp, MagicFit, CaaS or StoreLeads lists. Names alone don't say who is inside; the rules (pixel, event, days) do.

The login reaches 4 ad accounts

The connection runs on your personal Facebook login. It can also reach FDX Sports, Agentsy and a personal account. The agent must be hard-locked to Brevo PushOwl (act_1068538947813085), and the token expires about every 60 days.

Why so few campaigns: Meta's newer delivery system (Andromeda) rewards genuinely different creatives inside broad targeting, not many narrow ad sets. Every extra ad set splits the install volume Meta needs to learn. Each ad set needs about 50 installs a week to leave its learning phase.

Who selects: the agent, at build time. Each campaign template states which confirmed roles it uses (Retarget = Warm plus Always exclude; Cold = broad plus Always exclude). You approve each new campaign before launch. Missing audiences (for example the 14-day install-clickers) are specified by the agent exactly. They're created through the API if a create route turns out to exist, otherwise by you in Events Manager from the agent's recipe.

Cold targeting: broad (Advantage+ audience) within your countries, with installers excluded. The creative does the targeting: a batch built around "Shopify stores losing carts" finds those merchants. That's how Meta's current system works, and it beats narrow interests.

Keeping the account safe From Meta's rate-limit docs, Google's API policies and how tools like Birch and Optmyzr handle it. Sources are listed at the end.

What actually gets accounts restricted

  • Behaviour, not the tool. Meta publishes no rule saying API changes are judged differently from Ads Manager changes. The patterns tied to restrictions are repeated disapprovals, resubmitting a rejected ad without real changes, sudden budget jumps, payment failures and unfamiliar logins.
  • The biggest current risk is already in the account: 15 disapproved ads. The agent should read the reasons, and you decide whether to fix or appeal them. Nothing gets resubmitted automatically.
  • Hard API limits: 4 budget changes per ad set per hour, 10 spending-limit changes a day, and a shared hourly call quota per ad account. The agent's rules sit far below these: one budget change per ad set every 72 hours, and it never touches the spending limit.

Safety features to build

Account lock

Every write is checked against one allowed account, page and pixel. Anything else is refused in code.

Write budget

At most 20 writes a day across the account. One budget change per ad set per 72 hours, a 20% maximum step, at most +50% a week in total, never past the monthly cap.

Rate awareness

Reads Meta's usage header on every call, backs off at 75%, retries with exponential backoff, and never retries instantly.

Pre-launch policy check

Competitor names, the claims ledger, and Meta's sensitive categories (personal attributes, before and after, income claims) give each ad a risk score. High risk goes to you.

Disapproval stop

A disapproval pauses similar drafts, raises a card with Meta's reason, and blocks resubmission until the ad is really changed.

Learning protection

No edits to an ad set in learning unless a kill rule fires. Edits are batched so learning resets once, not repeatedly.

Alarms

Spend over 1.5x the daily plan, a CPI spike, a disapproval, or any change in account status: the agent stops that lane and alerts you.

Kill switch and digest

One switch stops all writes. A daily digest lists every action with its evidence and Undo.

Google Ads Starts after the treg sign-in, and runs more slowly than Meta by design.

  • Tracking: Shopify supports GA4 on the App Store listing, which sends shopify_app_install. Mark it as a key event in GA4 and import it into Google Ads. The first import takes about 2 days.
  • What the agent can do through treg: read everything and change budgets. It can't create campaigns there, so it prepares them as an Ads Editor file that you import. They land as drafts.
  • Bidding: Maximize conversions first. Switch to target CPA only after 15 installs in 30 days (30 or more is better). Move target CPA at most 15% at a time, with 2 weeks between moves.
  • New since August 2026: a budget-limited target-CPA campaign now spends up to its target. A target set above your real CPI quietly raises cost, so the agent keeps the target in line with actual results.
  • Structure: one Search campaign on high-intent terms (for example "shopify push notifications", "abandoned cart push"). Competitor names never appear in ad text. Performance Max or Demand Gen come only once Search is on target.

What I need from you

  1. Target CPI for an install, plus the most you'd tolerate (the hard ceiling).
  2. Monthly budget for PushOwl installs on Meta now, and on Google later.
  3. Countries and languages. The CaaS campaign ran US, CA, GB, AU, FR and DE.
